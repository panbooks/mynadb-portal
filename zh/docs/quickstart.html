快速入门指南

从源码构建并在本地试用 MynaDB。本指南涵盖 MynaDB 的构建、运行、写入数据和查询。

前置条件

  • 近期稳定版 Rust（本次验证工具链为 1.92.0）（通过 rustup 安装）
  • C/C++ 编译器、pkg-config、OpenSSL 开发文件及 protoc（部分平台的原生依赖还需要 CMake）
  • curl（用于测试 API）

第 1 步：构建和运行

bash 
# 克隆仓库
git clone https://github.com/panbooks/mynadb.git
cd mynadb

# 以 release 模式构建
cargo build --locked --profile fast-release

# 运行服务器
./target/fast-release/mynadb -c examples/quickstart.toml standalone

保持服务器运行，在另一个终端检查健康接口（应返回 HTTP 200 和 OK）：

curl --fail http://127.0.0.1:7000/health

开发状态：请先使用本地测试数据评估。示例仅绑定回环地址，关闭 WAL 和认证；重启前需成功执行 POST /flush。这不等于已验证 WAL 崩溃恢复。功能验证范围

第 2 步：写入数据

MynaDB 接受 InfluxDB Line Protocol 格式的数据：

Line Protocol Format 
<measurement>,<tag_key>=<tag_value> <field_key>=<field_value> [timestamp]

写入一些示例数据：

bash 
# 写入 CPU 和内存指标
curl -X POST http://localhost:7000/write/mydb -d '
cpu,host=server01,region=us-west usage=75.5,temp=45
cpu,host=server02,region=us-west usage=45.2,temp=38
cpu,host=server03,region=us-east usage=89.1,temp=52
memory,host=server01 used=16.5,total=32.0
memory,host=server02 used=24.8,total=64.0
memory,host=server03 used=12.2,total=32.0
'
💡 关于数据库

数据库（mydb）在首次写入时会自动创建，无需手动创建！

第 3 步：使用 SQL 查询

⚡ 即时查询可见性

无需刷盘！MynaDB 的 Memtable 为新写入的数据提供即时查询可见性。查询引擎会自动合并内存中（未刷盘）和 Parquet 文件中（已刷盘）的数据。

现在使用标准 SQL 查询您的数据：

基础查询

bash 
# 查询所有 CPU 数据
curl 'http://localhost:7000/query/mydb' -d 'SELECT * FROM cpu'

聚合查询

bash 
# 按主机计算平均 CPU 使用率
curl 'http://localhost:7000/query/mydb' \
  -d 'SELECT host, AVG(usage) as avg_cpu FROM cpu GROUP BY host'

结果：

[
  {"host": "server01", "avg_cpu": 75.5},
  {"host": "server02", "avg_cpu": 45.2},
  {"host": "server03", "avg_cpu": 89.1}
]

过滤查询

bash 
# 高 CPU 使用率的服务器
curl 'http://localhost:7000/query/mydb' \
  -d 'SELECT host, usage FROM cpu WHERE usage > 70 ORDER BY usage DESC'

JOIN 查询

bash 
# 关联 CPU 和内存数据
curl 'http://localhost:7000/query/mydb' -d "
SELECT c.host, c.usage as cpu_usage, m.used as memory_used
FROM cpu c
JOIN memory m ON c.host = m.host
"

第 4 步：列出表

查看数据库中可用的表：

bash 
curl http://localhost:7000/tables/mydb

结果：

{
  "catalog": "mydb",
  "tables": ["mydb.default.cpu", "mydb.default.memory"],
  "count": 2
}

第 5 步：Flush、重启与停止

此示例关闭 WAL。先成功 flush，再停止和重启；随后重复上面的 SQL 查询，检查已落盘数据。此流程不验证未落盘写入的崩溃恢复。

curl --fail -X POST http://127.0.0.1:7000/flush
./target/fast-release/mynadb -c examples/quickstart.toml stop
./target/fast-release/mynadb -c examples/quickstart.toml standalone

结束试用时，用同样的 stop 命令或 Ctrl+C 停止进程。示例数据和日志分别位于 data/quickstart 和 logs/quickstart；停止后再清理自己创建的测试文件。

总结

您已经成功完成了以下操作：

  • ✓ 构建并启动了 MynaDB
  • ✓ 使用 Line Protocol 写入时序数据
  • ✓ 立即查询数据（无需刷盘！）
  • ✓ 使用 SQL 进行聚合和 JOIN 查询
  • ✓ 列出可用的表
