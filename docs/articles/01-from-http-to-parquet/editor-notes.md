# 第一篇编辑与发布说明

## 发布文案

- 通用标题：从0到1实现一个分布式时序数据库（一）：用 Rust、Arrow 和 Parquet 打通写入与 SQL 查询
- 知乎备选：用 Rust 从零写一个时序数据库，第一版该怎么设计？
- 掘金备选：手写时序数据库 01：HTTP → Arrow → Parquet → SQL
- 摘要：从一条 CPU 指标出发，拆解数据模型、Arrow 批次、缓存刷盘、Parquet 分区文件和 DataFusion 查询，理解单机时序数据库第一版的核心设计。
- 建议话题：Rust、数据库、时序数据库、Apache Arrow、Parquet、DataFusion。

## 内容定位

正文按里程碑的设计主线展开，不再逐条复盘旧版本实现与修复。Point 保留指标 fields，数值列贯穿解析、缓存、文件写入与 SQL 示例；代码和接口均为精简设计示意，不宣称可直接复现某个历史标签，也没有展示未经运行验证的输出或性能数字。

八张配图提供 PNG、SVG 和 Mermaid 源文件。PNG 可上传至社区图片服务，再替换正文的相对链接。图片均为架构示意，未包含真实账户或用户数据。

## 发布准备

- 正文已按“快速理解第一版设计”精简，历史弯路与逐版本审计内容已去掉。
- 发布前在目标编辑器检查代码块、表格和图片排版，核对当天的投稿规则。
- 文章及图片仍在本地；当前未向知乎、掘金发布。

## 本地生成

修改正文或图源后，运行 `python3 build_assets.py` 重新生成配图和 `preview.html`。脚本依赖 Pillow、Markdown 和中文字体；通过 `MYNADB_ARTICLE_FONT` 指定字体文件。
