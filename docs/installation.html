Installation

Build from source for the current evaluation path. Binary and Docker validation status is documented below; system-service examples are deployment templates requiring separate verification.

System Requirements

Hardware planning

These are planning estimates, not tested minimum requirements. Compilation may need more memory and disk than runtime. This review uses Linux x86_64; other platforms are unverified.

Component Minimum Recommended
CPU 2 cores 4+ cores
Memory 2 GB 8+ GB
Storage 10 GB SSD 100+ GB NVMe SSD
Network 100 Mbps 1 Gbps+

Software

  • Operating System: Linux (Ubuntu 20.04+, Debian 11+, RHEL 8+, etc.)
  • Architecture: x86_64 (AMD64) or ARM64
  • Rust: Recent stable (review toolchain: 1.92.0; MSRV not established)

Binary release status

As of 2026-11-09, GitHub Release v0.0.1 has no binary assets. Build from source below; no x86_64 or ARM64 download archive has been validated in this review.

Build from Source

Building from source gives you the latest features and allows customization.

Prerequisites

In addition to Rust, install a C/C++ compiler, pkg-config, OpenSSL development files, and the Protocol Buffers compiler protoc. Native dependencies may also require CMake on some platforms.

bash 
# Install Rust (if not already installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Reload shell configuration
source $HOME/.cargo/env

# Verify Rust installation
rustc --version  # Record your toolchain; this review uses 1.92.0

Clone and Build

bash 
# Clone the repository
git clone https://github.com/panbooks/mynadb.git
cd mynadb

# Build release binary
cargo build --release --locked

# Binary is now at target/release/mynadb
./target/release/mynadb --version

# Optional: Install to system path
sudo cp target/release/mynadb /usr/local/bin/

Build Script

The following packaging script requires separate output validation; it does not establish that a downloadable release archive exists:

bash 
# Build and create release archive
./build.sh

# Output: mynadb-vX.X.X-linux-amd64.tar.gz

Docker validation status

Container builds and image publication have not been validated in this review, so no unverified official image pull command is provided. The repository Dockerfile is available for further testing; it is not a certified production deployment.

Systemd Service

Set up MynaDB as a systemd service for automatic startup and management.

Create Service User

bash 
# Create a dedicated user
sudo useradd --system --no-create-home --shell /bin/false mynadb

# Create data directory
sudo mkdir -p /var/lib/mynadb
sudo chown mynadb:mynadb /var/lib/mynadb

# Create config directory
sudo mkdir -p /etc/mynadb

Create Configuration File

toml 
# /etc/mynadb/config.toml

[server]
http_port = 7000
flight_port = 7001

[storage]
data_dir = "/var/lib/mynadb/data"

[cache]
flush_interval_secs = 30

[compaction]
min_files = 4
max_level = 5
max_concurrent_compactions = 8

[retention]
enabled = true
default_days = 30
interval_secs = 3600

Create Systemd Unit File

ini 
# /etc/systemd/system/mynadb.service

[Unit]
Description=MynaDB - High-Performance Time Series Database
Documentation=https://github.com/panbooks/mynadb
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=mynadb
Group=mynadb
ExecStart=/usr/local/bin/mynadb --config /etc/mynadb/config.toml
Restart=on-failure
RestartSec=5

# Resource limits
LimitNOFILE=65536
LimitNPROC=4096

# Security hardening
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/mynadb
PrivateTmp=true

# Environment
Environment=RUST_LOG=info

[Install]
WantedBy=multi-user.target

Enable and Start Service

bash 
# Reload systemd
sudo systemctl daemon-reload

# Enable service to start on boot
sudo systemctl enable mynadb

# Start the service
sudo systemctl start mynadb

# Check status
sudo systemctl status mynadb

# View logs
sudo journalctl -u mynadb -f

Verify Installation

After installation, verify MynaDB is running correctly:

Health Check

bash 
# Check HTTP health endpoint
curl http://localhost:7000/health

# Expected response:
{"status": "ok"}

Write Test Data

bash 
# Write test data
curl -X POST 'http://localhost:7000/write/testdb' \
  -d 'cpu,host=server01 usage=45.2'

# Flush to disk
curl -X POST http://localhost:7000/flush

# Query data
curl 'http://localhost:7000/query/testdb' \
  -d 'SELECT * FROM cpu'

Check Ports

bash 
# Verify ports are listening
ss -tlnp | grep -E '7000|7001'

# Expected output:
LISTEN  0  128  *:7000  *:*  users:(("mynadb",pid=1234,fd=3))
LISTEN  0  128  *:7001  *:*  users:(("mynadb",pid=1234,fd=4))
Installation Complete!

MynaDB is now installed and running. Continue to the Quick Start guide to learn how to use it, or see Configuration for advanced setup options.

Troubleshooting

Issue Solution
Port already in use Change http_port or flight_port in config.toml
Permission denied Check data directory ownership: chown -R mynadb:mynadb /var/lib/mynadb
Service won't start Check logs: journalctl -u mynadb -n 50
Out of memory Reduce full_compaction_max_concurrent in config
Slow queries Trigger compaction: curl -X POST http://localhost:7000/compact/mydb
